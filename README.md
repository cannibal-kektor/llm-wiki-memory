# LLM Wiki Memory

Автономный исследовательский PoC: один разрешённый полный TXT → один явно настроенный запрос локальной LLM → строгий JSON → проверка дословного происхождения → предпросмотр в консоли.

**Все кандидаты НЕПРОВЕРЕННЫЕ. «Проверка: ПРОЙДЕНА (PASS)» (`Validation: PASS`) означает только прохождение проверок структуры и буквального происхождения возвращённых кандидатов. Это не подтверждение юридического смысла, полноты, официального статуса или актуальности документа.** Предел — 32 кандидата. Даже успешный запуск не доказывает полного охвата документа. Достижение предела отдельно отмечается. Отсылки к недоступным актам остаются неразрешёнными.

Реализованы предпросмотр извлечения из TXT и отдельный локальный структурный снимок Docling для RTF/DOCX (этап 1.1, без LLM; PDF не проверен). Добавлен отдельный предварительный анализ готового Docling snapshot (1.2a, границы/домены нумерации 1.2a.1-A и консервативная иерархия 1.2a.1-B, без LLM). Консолидация, юридический верификатор, Wiki Markdown, сохранение результатов извлечения, Git-публикация, qmd и интеграция с БД отсутствуют. Первичные документы остаются юридическими источниками; Wiki задумана как производная навигация к ним. Существующий `ai-assistant` не меняется.

Документы проекта: [архитектура](docs/ARCHITECTURE.md), [план](docs/IMPLEMENTATION_PLAN.md), [правила агентов](AGENTS.md), [правила Claude Code](CLAUDE.md).

## Что дальше

Milestone 1 реализует только TXT-извлечение с одной непрерывной цитатой на кандидата. Этап 1.1 добавляет отдельный CLI структурного снимка Docling (см. [ниже](#структурный-снимок-rtfdocxpdf-этап-11)): RTF и DOCX успешно преобразованы, отдельные свойства структуры сопоставлены с известными потерями; юридическая/визуальная точность не установлена. PDF-путь реализован, но **не проверен** (нет пакетов моделей и весов). Извлечение утверждений по-прежнему принимает только TXT; снимок к нему не подключён.

Инкремент **1.2a** распознаёт предварительные структурные кандидаты (см. [ниже](#предварительная-правовая-структура-этап-12a)), **1.2a.1-A** — структурные границы и домены нумерации (см. [ниже](#границы-и-домены-нумерации-этап-12a1-a)), **1.2a.1-B** — консервативную иерархию (см. [ниже](#иерархия-единиц-этап-12a1-b)); фаза 1 ещё неполна. Порядок: **1.1** структурный снимок Docling → **1.2a** кандидаты/учёт блоков → **1.2a.1-A** границы и домены нумерации → **1.2a.1-B** структурная иерархия глава → статья и номерная внутри доменов → **1.2a.1-C** консервативные продолжения → **1.2b** явные ссылки и индексы → **1.3** детерминированные evidence ID и контракт нескольких доказательств → **1.4** Extraction Unit + Supporting Context и извлечение по единицам → **1.5** независимая юридическая проверка. Структура Docling, токенные чанки и правовые единицы различаются; точный текст снимка сам по себе не доказывает юридический смысл или полноту. Отсутствующие источники и существенный неразрешённый контекст требуют рассмотрения.

Затем сохраняется порядок: Knowledge Consolidation → Markdown Wiki с человеческим одобрением и одним Git writer → qmd опубликованного снимка → разрешённый адаптер корпуса только для чтения → автономная оценка поиска. Интеграция в `ai-assistant` возможна лишь после измерений и отдельного разрешения. Границы и решения — в [архитектуре](docs/ARCHITECTURE.md), зависимости и критерии приёмки — в [плане](docs/IMPLEMENTATION_PLAN.md).

## Запуск и сборка

Python **3.12+**. TXT CLI не имеет зависимостей времени исполнения; структурному снимку нужна необязательная зависимость `ingest` (см. отдельный раздел). Из корня проекта установка не нужна:

```bash
python3 -m llm_wiki --help
```

Сборка использует setuptools **68.1.2** и установленный `wheel`. При ранее описанной автономной проверке использовались системные setuptools 68.1.2 и wheel 0.42.0; в проектном `.venv` setuptools может отсутствовать. Пример сборки без скачивания зависимостей, с временными выходными каталогами:

```bash
BUILD_DIR=$(mktemp -d /tmp/llm-wiki-build.XXXXXX)
/usr/bin/python3 -m pip wheel --no-deps --no-build-isolation --no-index --no-cache-dir \
  --wheel-dir "$BUILD_DIR" .
python3 -m venv "$BUILD_DIR/env"
"$BUILD_DIR/env/bin/python" -m pip install --no-deps --no-index \
  "$BUILD_DIR/llm_wiki_memory-0.1.0-py3-none-any.whl"
```

Обычный `pip install .` с изоляцией сборки может скачивать зависимости сборки; это требует отдельного разрешения. Модели приложение не скачивает.

## Разрешения и локальные данные

`text/010_treb_KYT_Provider.txt` — реальный юридический текст о требованиях к заявителям на деятельность KYT-провайдера в белорусском ПВТ, **не вымышленная фикстура**. По сообщению оператора, использован экземпляр размером 50 995 байт; при обновлении этой документации файл не читался и его содержимое/метаданные повторно не проверялись. Подлинность, полнота, официальный статус, действующая редакция и даты действия независимо не установлены. Имя файла и `2026` в ID ниже — только метки оператора, не подтверждённые метаданные редакции.

Перед POST оператор должен отдельно разрешить обработку **этого текста этим сервисом**, учитывая журналирование/хранение провайдером, защиту транспорта, права доступа и допустимую нагрузку. `--approved-source` — явное подтверждение такого разрешения, а не автоматическое установление юридической правильности, прав на публикацию или отсутствия конфиденциальных данных. Частный IP сам по себе ничего из этого не доказывает. Обычный HTTP не шифрует текст и токен.

В репозиторий входят код, промпт и документация. Юридические документы не поставляются: каталог `text/` намеренно исключён через `.gitignore`, его локальные файлы не входят в индекс. После клонирования предоставьте собственный разрешённый UTF-8 TXT и явно укажите путь. Пример KYT ниже относится только к экземпляру, который оператор отдельно разместил в `text/010_treb_KYT_Provider.txt`.

Права/лицензия на публикацию исходников и их конфиденциальность не установлены. Не добавляйте юридические TXT принудительно и не используйте массовое `git add .`. Для частных материалов также предусмотрен игнорируемый `corpora/`. Локальные файлы при исключении из индекса не перемещались и не изменялись.

Локальный `text/001_to_be_resident.txt`, если он есть, не является входом этого этапа; не применять к нему обрезку или диапазоны строк. Старый демонстрационный файл удалён и не входит в индекс. Безвредные примеры для ручных проверок создавать только во временном каталоге.

## Конфигурация и команда KYT

| Параметр | Переменная окружения | Назначение |
| --- | --- | --- |
| `--endpoint` | `LLM_WIKI_ENDPOINT` | Обязательный базовый URL одобренного локального API, включая `/v1`, если нужен; добавляется `/chat/completions` |
| `--model` | `LLM_WIKI_MODEL` | Обязательный точный ID модели сервиса |
| `--timeout` | `LLM_WIKI_TIMEOUT` | Тайм-аут операции сокета 1–300 секунд; по умолчанию 60, не общий срок выполнения |
| `--response-format` | `LLM_WIKI_RESPONSE_FORMAT` | `text` по умолчанию либо явно выбранный `json_object` |
| — | `LLM_WIKI_API_KEY` | Необязательный Bearer-токен; не передавать аргументом CLI и не хранить в Git |

CLI имеет приоритет над окружением. Нет адреса, модели, токена или публичного провайдера по умолчанию. `.env` и `OPENAI_*` не читаются; обнаружение/запуск сервиса отсутствует. Разрешены только явные loopback, RFC 1918 IPv4 и IPv6 unique-local IP. Имена хостов, в том числе `localhost`, публичные IP, учётные данные в URL, query и fragment запрещены. Прокси окружения и перенаправления отключены, HTTPS использует обычную проверку сертификата.

**Команда ниже — локальный операторский пример: файл KYT должен быть предоставлен отдельно, обработка разрешена для выбранного сервиса, а сетевое подключение — соответствовать согласованной политике защиты данных.** Замените строки в угловых скобках на реальные одобренные настройки; это шаблоны, не рабочие значения IP/модели. Чтение `/v1/models` — отдельная операция чтения, а не разрешение на POST документа.

```bash
export LLM_WIKI_ENDPOINT="http://<ОДОБРЕННЫЙ_ЛОКАЛЬНЫЙ_IP>:8080/v1"
export LLM_WIKI_MODEL="<ТОЧНЫЙ_ID_ИЗ_/v1/models>"

time python3 -m llm_wiki text/010_treb_KYT_Provider.txt \
  --document-id pvt-kyt-provider-2026-preview \
  --approved-source --dry-run \
  --response-format json_object --timeout 300
echo $?
```

Путь и `--document-id` задаёт оператор. ID: 1–64 ASCII-буквы, цифры, `_` или `-`, первый символ — буква/цифра. `--approved-source` и `--dry-run` обязательны; старый `--synthetic` не поддерживается. Коды выхода: **0** — все проверки источника прошли; **1** — ошибка обработки, конфигурации, транспорта или валидации; **2** — неправильное использование CLI.

`--dry-run` **отправляет полный разрешённый TXT модели**. Он лишь не записывает Wiki, коммиты, индекс или результаты. Сервис модели может хранить запросы. Предпросмотр печатает утверждения и цитаты: **журналы терминала/сеанса и перенаправленный stdout могут содержать исходный текст**. Ошибки не печатают токены, адрес сервиса или тело ошибки сервера. Python может создавать игнорируемые `__pycache__`; для их отключения задайте `PYTHONDONTWRITEBYTECODE=1`.

## Контракт и проверка

Один полный UTF-8 TXT до **65 536 байт** читается как исходные байты, без нормализации пробелов/переводов строк. SHA-256 считается от этих байтов. Превышение лимита отклоняется до сети, без обрезки, парсера, разбиения или выбора строк.

Модель должна вернуть только следующий JSON; все поля обязательны, лишние запрещены. Это пример схемы, не результат извлечения KYT:

```json
{"claims": [{
  "source_document_id": "pvt-kyt-provider-2026-preview",
  "statement": "Одна атомарная норма с сохранёнными ограничениями.",
  "quote": "Точная непрерывная цитата из документа.",
  "conditions": [], "exceptions": [], "scope": null,
  "jurisdiction": null, "effective_date": null
}]}
```

`conditions` и `exceptions` — списки дословных фрагментов `quote`; `scope`, `jurisdiction`, `effective_date` — дословные фрагменты либо `null` (неизвестно). Даты не нормализуются и не выводятся из косвенных признаков. `statement` должен самостоятельно сохранять все существенные ограничения; детерминированная проверка не устанавливает его полноту, атомарность или соответствие юридическому смыслу цитаты.

Лимиты из `llm_wiki/validation.py`: 262 144 байта ответа, 1–32 кандидата, 2 000 символов `statement`, 8 000 символов `quote`, 1 500 символов уточнения, до 12 элементов в каждом списке уточнений. Некорректные типы, пустые строки, отсутствующие/лишние поля, повторные JSON-ключи, неконечные числа, небезопасные управляющие/форматирующие символы отклоняются. Markdown-обёртка JSON не исправляется. Промпт разрешает отказ через `claims: []`, однако текущий валидатор отклоняет пустой список; это не успешный пустой результат.

Проверяются доверенный ID источника, полное дословное вхождение `quote` в источник и каждого уточнения в `quote`. Python вычисляет смещения символов Unicode `[start, end)` от нуля, при повторе цитаты выбирает первое вхождение. Редакция и номер раздела остаются неизвестными. SHA-256 — снимок байтов, не юридическая редакция. Детерминированный ID кандидата зависит от источника и полей извлечения, не от семантической эквивалентности.

Ошибка схемы отклоняет ответ без печати сырого вывода. Ошибки происхождения видны по кандидатам, но отказ хотя бы одного отклоняет **весь пакет**. Даже если пакет прошёл, каждый кандидат остаётся НЕПРОВЕРЕННЫМ.

Транспорт: один синхронный POST Chat Completions, `model`, сообщения `system`/`user`, `stream: false`, `max_tokens: 8192`. Ожидается ровно один ответ `assistant` со строкой `content` и `finish_reason: "stop"`. Обрезка, отказ, инструменты, неправильная оболочка, тайм-аут и ошибки сети отклоняют пакет. Нет повторов и автоматической смены формата. `text` не добавляет параметр структурированного вывода; `json_object` добавляет `response_format: {"type": "json_object"}`. Поддержка JSON Schema/SDK не предполагается.

## Редактируемый системный промпт

Полный активный промпт: **`llm_wiki/prompts/legal_extraction_ru.txt`**, UTF-8. Редактируйте его непосредственно; изменения читаются при следующем запросе, кэша нет. `importlib.resources` загружает ресурс установленного пакета независимо от рабочего каталога. `pyproject.toml` явно включает его в wheel через `tool.setuptools.package-data`, даже при `include-package-data = false`.

`llm_wiki/llm.py` формирует `<<SCHEMA_EXAMPLE>>` через `json.dumps(example, ensure_ascii=False)` с доверенным `source_document_id`. `<<MAX_CLAIMS>>`, `<<MAX_STATEMENT_CHARS>>`, `<<MAX_QUOTE_CHARS>>`, `<<MAX_QUALIFIER_CHARS>>`, `<<MAX_QUALIFIERS>>` берутся из Python-констант `validation.py`. Не заменяйте маркеры вручную числами; каждый вид обязателен, повторения допускаются. Неизвестные, повреждённые или отсутствующие маркеры, отсутствие ресурса и ошибки UTF-8 приводят к русскому сообщению **до HTTP**; встроенного запасного промпта нет. Обычные JSON-скобки не интерпретируются как шаблон.

## Структурный снимок RTF/DOCX/PDF (этап 1.1)

`python -m llm_wiki.ingest` — отдельный от TXT CLI локальный путь: один разрешённый файл → upstream `DocumentConverter` Docling → JSON-снимок `DoclingDocument` и отдельный JSON-отчёт. LLM, Wiki, Git и индексация не вызываются; модули LLM не импортируются. Снимок — производное представление Docling, **не юридический оригинал**; его текстовая и структурная точность не проверяется автоматически.

Зависимость (скачивание пакетов требует отдельного разрешения): extra `ingest` = `docling-slim[format-docx,format-pdf]==2.138.0`. Метапакет `docling` не используется: он тянет torch и OCR. Проверено на Linux x86_64 с Python 3.12.3, docling-slim 2.138.0, docling-core 2.101.1, docling-parse 7.22.3, python-docx 1.2.0 и LibreOffice 24.2.7.2. Транзитивные версии не закреплены.

```bash
.venv/bin/python -m pip install 'docling-slim[format-docx,format-pdf]==2.138.0'
mkdir -p runtime/ingestion
unshare -rn .venv/bin/python -m llm_wiki.ingest <путь/к/файлу.RTF> \
  --document-id <id> --output-dir runtime/ingestion
echo $?
```

- **Вход:** обычный файл `.rtf`, `.docx` или `.pdf`, регистр расширения не важен. Сигнатура содержимого должна соответствовать расширению, а формат, определённый Docling, — совпасть с ним. `--max-bytes` (по умолчанию 50 МиБ, не более 200 МиБ) отклоняет файл без обрезки. SHA-256 считается по исходным байтам; Docling получает те же байты и имя файла без каталога.
- **Сеть:** CLI отказывает, если процессу видны сетевые интерфейсы кроме `lo`; запускать под `unshare -rn` или в равноценной изоляции. Дополнительно заданы `enable_remote_services=False`, `allow_external_plugins=False`, `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1`. Сами эти флаги не запрещают скачивание весов моделей; защитой служит сетевая изоляция.
- **RTF:** Docling преобразует RTF в DOCX локальным `soffice`: одноразовый профиль, макросы и обновление ссылок отключены, тайм-аут 120 с с завершением группы процессов. Upstream-helper использует временные файлы, удаляет временный каталог и передаёт DOCX как BytesIO; промежуточный DOCX не сохраняется как отдельный доступный артефакт и не хешируется. DDE, OLE и удалённые изображения upstream-настройками не закрыты, поэтому изоляция сети обязательна. Без `soffice` (или `--libreoffice`) отказ происходит до конвертации. По исходному коду Docling DOCX тоже может вызывать LibreOffice для растеризации отдельных изображений и диаграмм.
- **PDF:** `StandardPdfPipeline` с `do_ocr=False` (OCR выключен, скрытого OCR нет) и обязательным `--artifacts-path` — непустым локальным каталогом заранее полученных моделей. Также нужны пакеты `docling-slim[models-local]` (torch), которые не объявлены в extra. Без них CLI отказывает до конвертации. **PDF-конвертация не проверялась.** `--max-pages` (по умолчанию 300) передаётся Docling и действует только для PDF.
- **Результаты:** при SUCCESS — `<id>.docling.json`; при PARTIAL_SUCCESS — `<id>.INCOMPLETE.docling.json` (только для ручного разбора, код 1). После преобразования предусмотрена запись `<id>.report.json`; необработанные ошибки подсчёта/сериализации или записи могут помешать её завершению. FAILURE, SKIPPED, исключение, несовпадение формата или отсутствие текста дают только отчёт и код 1. Файлы создаются атомарно (временный файл + `link`) с правами 0600. Существующие результаты того же ID не перезаписываются: отказ происходит до конвертации. Если отчёт не записан после снимка, снимок считать неподтверждённым и удалить вручную.
- **Отчёт:** имя, формат, размер и SHA-256 источника; SHA-256 и размер сериализованного снимка; настройки конвейера; версии пакетов, Python и LibreOffice; статус и ошибки Docling; перехваченный журнал и предупреждения (до 50 записей по 500 символов — как и снимок, они могут содержать фрагменты документа); счётчики элементов; время; наблюдаемые CPU и пик RSS. Редакция, юридический статус, координаты и смещения в оригинале не заявляются.
- **Перехват журнала:** только на время `convert_source()` стандартный `Logger.callHandlers` временно заменяется маршрутом в ограниченную диагностику WARNING+; root/child handlers (включая `propagate=False`) не получают эти события, исходный метод восстанавливается даже при исключении. Уровни/фильтры логгеров сохраняются, Python warnings собираются отдельно. Это один CLI-процесс, без параллельных преобразований; print, прямые FD-записи, subprocess, собственный `callHandlers` и сообщения вне участка преобразования не перехватываются. Полный захват произвольного вывода не обещается.
- **Пределы:** жёсткий предел только один — тайм-аут subprocess LibreOffice. Время, CPU и RAM процесса Python не ограничены. Для машинных пределов нужна внешняя граница (`timeout`, `prlimit`, cgroup, контейнер); такая связка не проверялась.
- **Коды выхода:** 0 — SUCCESS с текстом (точность не проверена); 1 — отказ или неполный снимок; 2 — ошибка CLI.

Особенности представления, выявленные при ручной проверке:

- Нумерация, набранная текстом, остаётся в тексте элементов. Для автоматических списков Docling хранит маркер отдельно в `ListItem.marker` и вычисляет его сам: на синтетике вложенный пункт с видимым «1.» получил маркер «2.1.». Это не видимая нумерация оригинала.
- «Богатые» ячейки таблиц: плоский `text` ячейки повторяет дочерние элементы группы, на которую ссылается `ref`. При подсчёте и извлечении один и тот же текст нельзя учитывать дважды.
- Абзац со смешанным начертанием представлен `InlineGroup` из нескольких текстовых фрагментов; плоское чтение `texts` не заменяет обход дерева.
- На разрешённом RTF-образце 14 проверенных абзацев с прямым `\outlinelevel` сохраняют текст и прямое `w:outlineLvl` в диагностическом DOCX, но получают метку `text` в Docling. В установленном DOCX backend уровень читается из стиля, а не прямого свойства абзаца. Правовое назначение этих абзацев не установлено; метки снимка не исправляются.

- Хеш снимка воспроизводим для тех же байтов **и того же имени файла**: имя входит в `origin.filename` и `name` снимка.
- Документ, текст которого есть только в таблицах, принимается, если ячейки непусты; документ без текста получает FAILED.

## Предварительная правовая структура (этап 1.2a)

`python -m llm_wiki.structure` — отдельный локальный CLI для **принятой пары** Docling JSON / ingestion report. Нужен уже установленный docling-core **2.101.1** (extra `ingest`); поддержана схема DoclingDocument **1.10.0**. Установки, конвертации и сетевых обращений нет. Нет обращений к оригиналу, Extractor, Wiki или моделям. Хеши подтверждают согласованность пары, но не её подлинность: оператор выбирает доверенные разрешённые файлы. `NOT_VERIFIED` не повышается до юридической проверки.

Пример с безвредной синтетической парой, созданной локально при ручной проверке (она не поставляется в Git; для собственного запуска укажите свою принятую пару):

```bash
mkdir -m 700 runtime/structure/example-final
.venv/bin/python -m llm_wiki.structure \
  runtime/structure/manual-3/input/synthetic.docling.json \
  --report runtime/structure/manual-3/input/synthetic.report.json \
  --output-dir runtime/structure/example-final
```

Каталог должен заранее существовать внутри `runtime`, иметь права 0700 и игнорироваться Git. CLI выводит только счётчики и имена `<analysis-id>.structure.json` / `<analysis-id>.report.json` (с 1.2a.1-B — контракт `legal-structure/v3`, см. [ниже](#иерархия-единиц-этап-12a1-b)); ID вычисляется из снимка, политики и версии core. Файлы имеют права 0600, существующие не перезаписываются. Для повтора создайте другой частный каталог. Код выхода 0 означает запись предварительного результата с неразрешёнными блоками, 1 — отказ, 2 — неверные параметры. После сбоя между двумя атомарными записями возможен одиночный файл: результат завершён только при наличии отчёта с совпадающим хешем структуры.

Просмотр владельцем в локальном редакторе: `units` содержит тип/номер/родителя, основания, неопределённости (в v2 — машинные коды, пояснения в `codes`) и упорядоченные `source_refs`; `blocks` — учёт каждого узла; `table_cells` — отдельный учёт ячеек. По адресам можно открыть соответствующие элементы **локального** исходного JSON, не публикуя текст или отчёт. `represented_by` у InlineGroup/rich cell показывает альтернативное представление, которое нельзя повторно считать абзацем. Исходный текст в артефакты структуры не копируется, но сами артефакты также частные. У разрешённой реальной пары результаты этой проверки лежат в `runtime/structure/manual-3/real-a/` и `real-b/`.

Правила `legal-cues/1.2a-v1` (до 1.2a.1-B; текущие правила родителей — [ниже](#иерархия-единиц-этап-12a1-b)): изолированное `ГЛАВА N`, начало `Статья N.` либо только `Статья N`; положительные арабские числа до четырёх цифр. ### Иерархия единиц (этап 1.2a.1-B)

Тот же CLI пишет контракт `llm-wiki-memory/legal-structure/v3`, отчёт `structure-report/v3`, политика `legal-cues/1.2a.1-B-v2`; ID отличаются от v2 и от результатов B-v1, прежние файлы не перезаписываются. Поля `boundaries`, `numbering_markers`, `quoted_spans`, `numbering_domains` не изменены. Правила — [архитектура, раздел 2.4](docs/ARCHITECTURE.md#24-иерархия-единиц--этап-12a1-b); кратко:

- **Структурная связь** «документ → глава → статья» может пересекать домены нумерации: каждая статья открывает свой домен, а глава остаётся её областью. Область главы закрывается или блокируется:
  - следующей главой;
  - разделом, приложением, грифом, названием акта или заголовком: это контейнеры, которые не являются единицами (`container_not_modeled`);
  - нераспознанным маркером (в т. ч. «§ N.» и «Статья N <строчное слово>»), сбросом «1.», текстом изменения без кавычек (`scope_uncertain`);
  - цитатой.
- **Номерная связь** только внутри одного домена:
  - «N.» → статья, если домен открыт самой статьёй;
  - «N.M.» → «N.» и «N.M.K.» → «N.M.» — только при точном непосредственном префиксе у ближайшего предшествующего номера, который встречается в домене один раз.
- Неустановленный родитель остаётся `null`, со статусом `review_required`, машинной причиной `parent_basis` и доказательствами `parent_evidence`. `parent_evidence` — прямое доказательство решения, не полная трасса: пересечённые барьеры не перечисляются, а при структурной блокировке указана последняя блокировка перед единицей, не обязательно главная причина ([архитектура, раздел 2.4](docs/ARCHITECTURE.md#24-иерархия-единиц--этап-12a1-b)). Набранные номера получают нейтральный вид `numbered` (не пункт/часть). Номера списков Docling и ячейки таблиц единиц не дают.

## Наблюдения экспериментов и ручная проверка

По сообщению оператора, одна реальная локальная проба `text/010_treb_KYT_Provider.txt` (50 995 байт) дала **7 кандидатов примерно за 1 мин 49 с (~109 с): 3 технических PASS, 4 FAIL из-за недословных цитат; весь пакет отклонён, Wiki не опубликована**. Оператор отметил смысловую неполноту части прошедших кандидатов и неполный охват документа. Это единичное исследовательское наблюдение, не бенчмарк, не независимая юридическая оценка и не успешная приёмка извлечения. Исходные выдержки и полный ответ модели здесь не приводятся; нового запуска при обновлении документации не было.

Исторические операторские эксперименты, а не результаты текущего запуска KYT: ранее наблюдаемый llama.cpp рекламировал GPT-OSS 120B MXFP4 (первоначально оператор называл семейство 20B). JSON-режим принимался сервисом. Это не независимая проверка весов, размера или версии развёртывания. Сообщённый рабочий контекст — **50 176 токенов**, не безграничный и не размер обучающего контекста.

Ответы иногда меняли даже одну букву цитаты или регистр уточнения; `statement` мог терять область действия, время или исключения, в том числе при успешной технической проверке. В ранее документированном запуске на вымышленном тексте HTTP 200 дал два кандидата, но CLI завершился 1: цитата и уточнения не совпали дословно; отдельное утверждение потеряло временное ограничение. Другие сообщённые оператором пробы показали изменчивость времени выполнения и тайм-аутов. Настройка промпта не гарантировала стабильную точность. Эти пробы — исследовательские, не юридический бенчмарк. Успешное реальное извлечение KYT здесь не заявляется.

Сценарии ручной проверки реализации при изменениях: `python3 -m compileall -q llm_wiki`, `python3 -m llm_wiki --help`, `git diff --check`, `git diff --cached --check`; автономная сборка и установка wheel во временное окружение; временный локальный HTTP-стаб с безвредным текстом для корректного ответа, изменённых цитат/уточнений, неверного ID и отказа всего пакета. Отсутствующие флаги, плохой путь/UTF-8, слишком большой вход, неверная конфигурация и повреждённый промпт должны завершаться до HTTP. При этом документационном обновлении проверяются только diff и документация; CLI, сборка и модельные эксперименты не запускались. Набор автоматизированных тестов/CI не добавляется. Юридические TXT не входят в индекс; исходные байты не нормализовать ради проверок пробелов.

Большой промпт, документ около 50 КБ и бюджет ответа 8 192 токена могут исчерпать контекст/время сервиса. Тайм-аут сам по себе не доказывает дефект кода. При разрешённой реальной проверке допустим один последовательный запрос, с последующей проверкой смысловых ограничений и неполного охвата; нельзя ослаблять контракт ради успешного ответа.
